# ממשק קליטת ספקים — Priority ERP

ממשק ווב חיצוני לפתיחת **ספקים חדשים** בפריוריטי, ישירות דרך ה-REST API (OData).
לא מדובר בהכנת קובץ טעינה — הרשומה נכתבת לפריוריטי בזמן אמת, ולכן הממשק בנוי
סביב שלושה עקרונות:

1. **מאובטח** — פאנל התחברות עם משתמשים משלו; אין מצב פתוח.
2. **אימות בסמס לפני *כל* טעינה** — קוד חד-פעמי שקשור לרשומה הספציפית.
3. **ולידציה לפי הגדרת המסך** — חובה, אורך, טיפוס ודגלים נלקחים מייצוא עמודות
   המסך של פריוריטי, ונאכפים בשרת.

כתובת: **`/intake/`** (למשל `http://127.0.0.1:5000/intake/`).

## מסלול המשתמש

```
התחברות ➜ 1 זהות הספק ➜ 2 פרטי התקשרות ➜ 3 תנאי רכש ➜ 4 הנהלת חשבונות
        ➜ 5 סיכום ➜ שליחת קוד לסמס ➜ הזנת הקוד ➜ טעינה לפריוריטי ➜ יומן
```

בכל שלב מוצגים 7–9 שדות בלבד. שדה שגוי נצבע ומקבל הסבר בעברית מתחתיו; אזהרות
(טלפון/דוא"ל/ח.פ. חשודים) אינן חוסמות. מעבר שלב אפשרי רק כשהשלב תקין.

## הפעלה מקומית

```bash
cd file-loader
```

ואז בדפדפן: **http://127.0.0.1:5000/intake/**

בהרצה הראשונה (ומקומית בלבד) נפתח מסך **הקמה ראשונית** ליצירת משתמש המנהל.
בענן — ראו "פריסה" בהמשך.

## הגדרת החיבור לפריוריטי

מסך **הגדרות** (מנהל בלבד) → כרטיס "חיבור לפריוריטי":

| שדה | ערך |
|---|---|
| כתובת שירות OData | `https://<שרת>/odata/Priority/<tabula.ini>/<חברה>` |
| שיטת הזדהות | טוקן (PAT) / משתמש API וסיסמה / Bearer |
| טוקן | הטוקן מטופס **REST Interface Access Tokens** בפריוריטי |
| אימות תעודת SSL | להשאיר מסומן; לבטל רק מול שרת on-prem עם תעודה עצמית |

לחצן **בדיקת חיבור** מבצע `GET SUPPLIERS?$top=1` ומדווח בעברית מה קרה
(401 = טוקן שגוי, 404 = כתובת/חברה שגויה, וכו').

> **הזדהות בטוקן:** פריוריטי מצפה ל-Basic authentication שבו הטוקן הוא *שם
> המשתמש* והמילה הקבועה `PAT` היא הסיסמה. הממשק עושה זאת לבד.

הטוקן נשמר במסד **מוצפן** (AES-שכבתי מבוסס HMAC-SHA256, מפתח ממשתנה הסביבה
`INTAKE_SECRET`), ולעולם אינו מוחזר לדפדפן — גם לא במסך ההגדרות.

## אימות בסמס (OTP)

לפני כל טעינה נשלח קוד בן 6 ספרות. הקוד:

* נשמר **מגובב בלבד** (PBKDF2), לא בטקסט גלוי;
* תקף 5 דקות (ניתן לשינוי), עד 5 ניסיונות;
* **חד-פעמי** — אחרי טעינה מוצלחת הוא נצרב;
* **קשור לנתונים** — הקוד נחתם על טביעת אצבע של פרטי הספק. שינוי פרט כלשהו
  אחרי האימות מבטל אותו ודורש קוד חדש. כך אי אפשר לאשר ספק אחד ולטעון אחר.

### לאיזה מספר

| מדיניות | משמעות |
|---|---|
| `רק המספר הרשום למשתמש` (ברירת מחדל) | הקוד נשלח למספר שמנהל המערכת הגדיר למשתמש |
| `המשתמש בוחר מספר` | המשתמש מקליד מספר בכל טעינה |

### ערוצי שליחה

| ערוץ | מה להגדיר |
|---|---|
| `console` | כלום — הקוד נכתב ליומן השרת. **לפיתוח בלבד** |
| `webhook` | כתובת + טוקן. נשלח `POST` עם `{phone, code, message, sender}` — מתאים לכל שער סמס ישראלי |
| `inforu` | שם משתמש, טוקן ושם שולח |
| `twilio` | Account SID, Auth Token ומספר שולח |

בפריסה ציבורית ערוץ `console` **אינו** מציג את הקוד במסך.

## הרשאות

| תפקיד | מה מותר |
|---|---|
| קולט ספקים | לפתוח ספקים, לראות את היומן **שלו** |
| מנהל מערכת | בנוסף: הגדרות, ניהול משתמשים, כל היומן |

הגנות נוספות: גיבוב סיסמאות PBKDF2-SHA256 (240K סיבובים, מלח לכל משתמש),
נעילת חשבון ל-15 דק' אחרי 5 כשלונות, מגבלת קצב על התחברות ועל שליחת קודים,
אסימון CSRF בכל פעולה משנה, ניתוק אחרי 30 דק' חוסר פעילות (ולכל היותר 12 שעות),
ו-cookie מסוג HttpOnly + SameSite=Lax (ו-Secure בענן).

## הוולידציות — מאיפה הן מגיעות

`intake/fields_SUPPLIERS.yaml` הוא קטלוג 135 השדות של מסך הספקים, שנוצר
אוטומטית מייצוא עמודות המסך:

```bash
python -m intake.import_screen_spec intake/screens/SUPPLIERS_columns.xlsx SUPPLIERS
```

| עמודה בייצוא | מה היא קובעת |
|---|---|
| `קריאה/חובה/יתרה` = `M` | שדה חובה — הטופס לא ייתן להמשיך בלעדיו |
| `קריאה/חובה/יתרה` = `R` | שדה לקריאה בלבד (תיאור מחושב) — **לא ניתן להצגה בטופס** |
| `בולאני?` = `Y` | מוצג כ"כן / לא" ונשלח כ-`Y`/`N` |
| `טיפוס` | `CHAR`/`RCHAR` טקסט · `INT` שלם · `REAL` עשרוני · `DATE` תאריך |
| `רוחב` | אורך מרבי — נאכף גם בדפדפן וגם בשרת |
| `דיוק עשרוני` | מספר ספרות אחרי הנקודה |
| `כותרת` | הכותרת בעברית שמוצגת למשתמש |

שדות שהם מזהים פנימיים של פריוריטי (`SUP`, `ACCOUNT`, כל מה שכותרתו מסתיימת
ב-`(ID)`) מסומנים `system` ואינם ניתנים להזנה.

**מה מוצג בפועל** נקבע ב-`intake/form_SUPPLIERS.yaml` — חלוקה לשלבים, סדר,
כותרות ידידותיות ורשימות ערכים. להוספת שדה לטופס מספיק להוסיף שורה:

```yaml
- field: SHIPPERNAME
  label: חברת הובלה
  help: הקוד מטבלת חברות ההובלה.
```

שדה שאינו בקטלוג, או שדה `R`/`system` — ייפסל בטעינת הטופס עם הודעה ברורה.
30+ שדות רשות נוספים כבר מוגדרים תחת `advanced:` ומוצגים כשמפעילים
"שדות נוספים" בהגדרות.

## מה נשלח לפריוריטי

`POST {service_url}/SUPPLIERS` עם גוף JSON. הכללים:

* שדה ריק **אינו נשלח** — כדי לא לדרוס ברירות מחדל של פריוריטי;
* `INT`/`REAL` נשלחים כמספרים, לא כמחרוזות;
* תאריך נשלח כ-`YYYY-MM-DDT00:00:00Z`;
* דגלים נשלחים כ-`"Y"` / `"N"`;
* לפני הכתיבה נבדק שמספר הספק אינו קיים כבר (`$filter=SUPNAME eq '...'`).

**מספר ספק ריק** = פריוריטי יקצה מספר לפי המונה שלכם, והמספר שהוקצה מוצג
במסך הסיום ונשמר ביומן.

## פריסה בענן (Render / Vercel / Docker)

הממשק רץ בתוך אותה אפליקציה של כלי הכנת הקבצים, ולכן אין מה לפרוס בנפרד.
משתני הסביבה:

| משתנה | חובה | תיאור |
|---|---|---|
| `SECRET_KEY` | ✔ | חתימת ה-session. בלעדיו ה-session לא שורד הפעלה מחדש |
| `INTAKE_SECRET` | ✔ | מפתח להצפנת הטוקן של פריוריטי במסד |
| `INTAKE_ADMIN_USER` | ✔ (בענן) | שם המנהל הראשון — נוצר אוטומטית בהפעלה |
| `INTAKE_ADMIN_PASSWORD` | ✔ (בענן) | סיסמת המנהל הראשון |
| `INTAKE_ADMIN_PHONE` | ✖ | טלפון המנהל לקבלת קודי אימות |
| `DATABASE_URL` | ✖ | Postgres. בלעדיו — SQLite מקומי |
| `INTAKE_PRIORITY_URL` | ✖ | ערך פתיחה לכתובת השירות |
| `INTAKE_PRIORITY_TOKEN` | ✖ | ערך פתיחה לטוקן (עדיף על הקלדה בטופס) |
| `INTAKE_OTP_CHANNEL` / `INTAKE_OTP_ENDPOINT` / `INTAKE_OTP_USER` / `INTAKE_OTP_SECRET` / `INTAKE_OTP_SENDER` | ✖ | הגדרות שער הסמס |

בפריסה ציבורית **בלי** `INTAKE_ADMIN_USER`/`INTAKE_ADMIN_PASSWORD` הממשק חוסם
את עצמו ומציג הודעת הגדרה — במקום להיפתח לכל דורש.

> **Vercel:** מערכת הקבצים לקריאה בלבד ומצב הריצה אינו נשמר בין קריאות —
> הגדירו `DATABASE_URL` (Postgres), אחרת המשתמשים וההגדרות ייעלמו.

## הוספת מסך נוסף (לקוחות, פריטים…)

1. ייצאו מפריוריטי את עמודות המסך לאקסל ושמרו ב-`intake/screens/`.
2. `python -m intake.import_screen_spec intake/screens/CUSTOMERS_columns.xlsx CUSTOMERS`
3. צרו `intake/form_CUSTOMERS.yaml` (העתיקו את קובץ הספקים כנקודת פתיחה).
4. עדכנו את `SCREEN` ב-`intake/views.py`, או הוסיפו בורר מסך.
