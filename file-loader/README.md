# כלי הכנת קבצי טעינה לממשקי File Load של Priority ERP

כלי Python למיישמי פריוריטי: מקבל קובץ אקסל גולמי (למשל ייצוא ממערכת קודמת),
מנקה ומאמת את הנתונים לפי **קובץ מיפוי** שמגדיר את מסך היעד, ומייצר **קובץ טעינה מוכן**
ל-Interface (File Load) בפריוריטי — בסדר עמודות, קידוד ומפריד שתואמים בדיוק להגדרת הממשק.

שורות שנכשלות בוולידציה **אינן** נכנסות לקובץ הטעינה — הן נכתבות לקובץ נפרד עם סיבת הפסילה
בעברית, כדי שאפשר לתקן ולהריץ שוב רק אותן.

## שימוש

```bash
python main.py --input customers.xlsx --screen CUSTOMERS [--sheet "גיליון1"] [--dry-run]
```

| פרמטר | חובה | תיאור |
|---|---|---|
| `--input`  | ✔ | נתיב לקובץ הקלט הגולמי (`.xlsx` / `.txt` / `.dat` / `.csv`) |
| `--screen` | ✔ | שם המסך — נטען אוטומטית מ-`mappings/<SCREEN>.yaml` |
| `--sheet`  | ✖ | שם הגיליון בקובץ (ברירת מחדל: הגיליון הראשון) |
| `--header-row` | ✖ | מספר שורת הכותרת (החל מ-1). ברירת מחדל: זיהוי אוטומטי |
| `--dry-run`| ✖ | ולידציה בלבד — בודק את הנתונים **בלי** לייצר קובץ טעינה |

### ניסיון מהיר

```bash
python make_sample.py            # יוצר sample_customers.xlsx עם מקרי-קצה
python main.py --input sample_customers.xlsx --screen CUSTOMERS
```

## ממשק וובי (העלאת קובץ מהדפדפן)

מי שמעדיף לא לעבוד מה-CLI יכול להשתמש בממשק וובי מקומי: גוררים קובץ אקסל,
בוחרים מסך, ומקבלים כפתורי הורדה לקובץ הטעינה ולשורות הפסולות — עם דוח על המסך.
**הכל רץ מקומית; הקובץ לא נשלח לשום שרת חיצוני.**

```bash
pip install -r requirements.txt   # כולל flask
python webapp.py
```

ואז לפתוח בדפדפן: **http://127.0.0.1:5000**

הממשק עוטף את אותה ליבת עיבוד של ה-CLI, כך שהתוצאה זהה בשתי הדרכים.

### מיתוג ונושא (לוגו / רקע בהיר-כהה)

- **לוגו:** כברירת מחדל מוצג לוגו מובנה. כדי להציג את הלוגו שלכם — שמרו קובץ
  `assets/logo.png` (או `.svg`/`.jpg`) והוא יוצג אוטומטית בכל המסכים.
- **רקע בהיר/כהה:** כפתור **🌙/☀️** בפינת המסך מחליף בין רקע לבן לרקע כהה,
  והבחירה נשמרת. ברירת המחדל עוקבת אחר הגדרת המערכת.
מסך היעד נבחר מרשימה שנבנית אוטומטית מקבצי המיפוי שבתיקיית `mappings/`.

### טבלת טעינה אינטראקטיבית (תיקון שגיאות במקום)

אחרי העלאת הקובץ מוצגת **טבלת טעינה**: כל שורה מהאקסל בעמודות היעד של פריוריטי.

- **תאים שגויים נצבעים באדום** עם סימן `!` — ריחוף עם העכבר מציג את סיבת השגיאה.
- **מתקנים את הערך ישירות בתא**, לוחצים **🔄 בדוק מחדש** — הטבלה נצבעת מחדש והמונים מתעדכנים.
- **מוחקים שורה מיותרת** בלחיצה על 🗑 (למשל שורות סיכום/כותרת שהסתננו לקובץ).
- **מתעלמים מבעיה ומייצאים בכל זאת** — לחיצה על 🚫 בשורה מסמנת אותה כ"מיוצאת למרות
  הבעיה" (עובד גם על שגיאות אדומות, לא רק אזהרות). כפתור **🚫 התעלם מאזהרות** בסרגל
  מסמן בבת אחת את כל שורות האזהרה. שורות מסומנות נכללות בקובץ הטעינה ומודגשות בכחול.
- **מסדרים עמודות בגרירה** — גוררים כותרת עמודה (⋮⋮) למקום הרצוי. קובץ הטעינה
  מיוצא בסדר שנקבע בטבלה, כדי להתאים בדיוק להגדרת ה-Interface שלך בפריוריטי.
- **מרחיבים/מצמצמים רוחב עמודה** — גוררים את **קצה כותרת העמודה** (↔) לרוחב הרצוי,
  לנוחות קריאה של תאים ארוכים.
- העריכה עוברת דרך אותה לוגיקה: הקלדת `כן` בשדה מע"מ תמופה ל-`Y`, תאריך יעוצב ל-`dd/mm/yy` וכו'.
- עמודות של **ערך קבוע** (ללא `source`) מוצגות אפורות ואינן ניתנות לעריכה.
- כשמוכן — **⬇ צור קובץ טעינה**. הקובץ נבנה מהשורות התקינות; אם נותרו שורות שגויות,
  מתקבל גם קובץ `rejected.xlsx` עם סיבת הפסילה, והממשק מיידע כמה שורות לא נכללו.

### מיפוי עמודות דינמי (Excel → שדה)

הטבלה מתאימה את עצמה לכל קובץ אקסל. מעל הטבלה יש פאנל **"מיפוי עמודות"**:

- לכל שדה יעד מוצגת **רשימת בחירה** של העמודות שבקובץ האקסל — עם הבחירה שזוהתה
  אוטומטית (לפי הכינויים) מסומנת מראש.
- **שדה שלא זוהה אוטומטית** (במיוחד שדה חובה) מודגש באדום — פשוט **בוחרים מהרשימה**
  איזו עמודת אקסל מזינה אותו, והטבלה מחושבת מחדש מיד.
- כך אין צורך שהכותרות באקסל יתאימו בדיוק — אפשר למפות ידנית כל קובץ לממשק.

### מנוע תנועות יומן (JOURNAL)

במסך שקובץ המיפוי שלו כולל קטע `journal:` (כיום `JOURNAL`) מופיע מעל הטבלה סרגל
**"תנועות יומן"** עם שלוש פעולות חשבונאיות:

- **בדיקת תנועות** — מקבצת את השורות לפי מספר תנועת היומן ובודקת איזון חובה/זכות,
  אחידות תאריכים ושורות שכל הסכומים בהן 0.
- **איזון תנועות** — סוגרת אוטומטית הפרשי עיגול עד לסף שהמיישם מגדיר.
- **טיוב מט"ח** — מנקה ומעתיקה את עמודות המט"ח לפי המטבע הראשי/המשני.
- **המטבע הראשי והמשני נבחרים במסך ההעלאה** (ונשמרים עם הטעינה, כולל בהיסטוריה);
  ספי האיזון נשארים בסרגל שבטבלה כי הם כיול פר-פעולה.
- בקובץ גדול הטבלה מציגה רק שורות בעייתיות, אך הבדיקות רצות על **כל** רשומות הקובץ.

> תיעוד מלא — כללי החשבונאות, תפקידי העמודות, מגבלות וסדר עבודה מומלץ:
> **[JOURNAL.md](JOURNAL.md)**

### טיפול בקבצים "קשים"

- **שורת כותרת שאינה הראשונה:** קבצי יצוא רבים (למשל מחשבשבת) מוסיפים שורות
  כותרת/תאריך מעל הנתונים. הכלי **מזהה אוטומטית** את שורת הכותרת לפי שמות העמודות
  שבמיפוי. אפשר גם לכפות ידנית — שדה "שורת כותרת" בטופס ההעלאה, `--header-row` ב-CLI,
  או `header_row:` בקובץ המיפוי.
- **קבצים גדולים (עשרות אלפי שורות):** הכלי מעבד את כל הקובץ, אך בטבלה מציג **רק את
  השורות שדורשות תיקון** — השורות התקינות נשמרות בצד השרת ונכללות בקובץ הטעינה הסופי.
  כך הדפדפן נשאר מהיר גם עם 40,000 שורות. הטבלה כוללת עימוד וסינון "הצג רק שגויות".

בתיקייה `examples/` יש קבצי אקסל מוכנים לגרירה לממשק או להרצה מה-CLI:

| קובץ | מסך (`--screen`) | מה הוא מדגים |
|---|---|---|
| `customers_clean.xlsx` | `CUSTOMERS` | 5 לקוחות תקינים — נטענים במלואם |
| `customers_messy.xlsx` | `CUSTOMERS` | ניקיון אוטומטי + כל סוגי הפסילות |
| `items.xlsx` | `ITEMS` | פריטים/מק"ט — מיפוי יחידות מידה, מחיר, ברקוד |
| `suppliers.xlsx` | `SUPPLIERS` | ספקים — קודי מטבע, אימייל, טלפון |

לדוגמה:

```bash
python main.py --input examples/items.xlsx --screen ITEMS
```

את הקבצים אפשר לשחזר בכל עת עם `python make_examples.py`.
בנוסף ל-`CUSTOMERS` מצורפים קבצי מיפוי לדוגמה גם ל-`ITEMS` (מסך PART) ו-`SUPPLIERS`.

מיפוי `CUSTOMERS` הוא **מאוחד** — בזכות כינויים (aliases) הוא טוען גם קבצי לקוחות
רגילים וגם אינדקס חשבונות מיצוא **חשבשבת** (כותרת שאינה בשורה הראשונה מזוהה אוטומטית),
לאותו ממשק לקוחות, בלי מיפוי נפרד.

## קבצי הפלט (בתיקיית `output/`)

| קובץ | מתי נוצר | תוכן |
|---|---|---|
| `<SCREEN>_load.txt` / `.csv` | תמיד (אלא אם `--dry-run`) | קובץ הטעינה לפריוריטי — בסדר, מפריד וקידוד לפי המיפוי |
| `<SCREEN>_rejected.xlsx` | אם יש שורות פסולות | עמודות המקור המקוריות + עמודות **"שורה במקור"** ו-**"סיבת פסילה"** |
| `<SCREEN>_report.txt` | תמיד | דוח הסיכום (זהה למה שמוצג במסך) + פירוט מלא של אזהרות הקידוד |

> תיקיית `output/` מנוקה מ-git (הקבצים נוצרים בכל ריצה).

### תהליך העבודה המומלץ
1. הרץ את הכלי על קובץ המקור.
2. פתח את `<SCREEN>_rejected.xlsx`, תקן את השורות לפי עמודת **"סיבת פסילה"**.
3. שמור את הקובץ המתוקן והרץ את הכלי שוב — **רק** על השורות שתוקנו.
4. חזור עד שאין שורות פסולות, ואז טען את `<SCREEN>_load.txt` בפריוריטי.

## קובץ המיפוי — מקור האמת היחיד

לכל מסך יעד יש קובץ `mappings/<SCREEN>.yaml`. הקובץ מגדיר את פורמט הפלט ואת מיפוי העמודות.

```yaml
screen: CUSTOMERS
interface_name: XXXX_LOADCUST      # שם ה-Interface בפריוריטי (תיעוד בלבד)
delimiter: tab                     # tab / comma / pipe
encoding: windows-1255             # windows-1255 (און-פרם) / utf-8
date_format: "%d/%m/%y"           # פורמט התאריך בפלט
include_header: false              # האם לכתוב שורת כותרת בפלט
key_fields: [CUSTNAME]             # שדות לבדיקת כפילויות
columns:                           # הסדר כאן = סדר העמודות בפלט!
  - source: "מספר לקוח"           # כותרת העמודה באקסל המקור
    target: CUSTNAME               # שם השדה בפריוריטי
    required: true
    max_length: 15
    transform: [strip]
  - source: "חייב מעמ"
    target: VATFLAG
    value_map: {"כן": "Y", "לא": "N"}
    default: "Y"
  - target: STATDES                # ללא source = ערך קבוע לכל השורות
    default: "פעיל"
```

### הגדרות ברמת המסך

| מפתח | ברירת מחדל | תיאור |
|---|---|---|
| `screen` | — | שם המסך |
| `interface_name` | — | שם ה-Interface בפריוריטי (תיעוד) |
| `delimiter` | `tab` | מפריד העמודות: `tab` / `comma` / `pipe` |
| `encoding` | `windows-1255` | קידוד הפלט: `windows-1255` / `utf-8` |
| `date_format` | `%d/%m/%y` | פורמט התאריך בפלט. ברירת המחדל היא **תמיד `dd/mm/yy`** (למשל `23/07/26`) — חלה גם אם המפתח הזה מושמט |
| `header_row` | (זיהוי אוטומטי) | מספר שורת הכותרת (החל מ-1), לקבצים שבהם הכותרת אינה בשורה הראשונה. אם מושמט — הכלי מזהה אוטומטית לפי שמות ה-`source` |
| `include_header` | `false` | האם לכתוב שורת כותרת (שמות ה-target) בפלט |
| `key_fields` | — | רשימת שדות `target` לבדיקת כפילויות |
| `journal` | — | קטע תפקידי העמודות למנוע תנועות היומן. **נוכחותו** היא מה שמציג את סרגל היומן בטבלה — ראו [JOURNAL.md](JOURNAL.md) |
| `require_source` | — | רשימת `target`ים שחייבים ערך במקור; שורה בלעדיהם מסוננת עוד לפני הטבלה (לסינון שורות כותרת/יתרה בכרטסת) |
| `exclude_if_all_zero` | — | רשימת `target`ים של סכומים; שורה שכולם בה 0/ריק נפסלת ולא תיטען |
| `min_row_values` | — | מספר התאים הלא-ריקים המינימלי כדי שהשורה תישרד את שלב הניקוי |

### הגדרות ברמת עמודה (`columns`)

| מפתח | תיאור |
|---|---|
| `source` | כותרת העמודה באקסל המקור. אפשר גם **רשימת כינויים** (`["מספר לקוח", "מפתח חשבון"]`) — הכלי יבחר את הכינוי שקיים בקובץ. **בהשמטה** — העמודה מקבלת ערך קבוע (`default`) בכל השורות |
| `target` | **חובה.** שם השדה בפריוריטי (הכותרת בקובץ הטעינה) |
| `required` | `true` = השדה חייב ערך; שורה עם ערך ריק תיפסל |
| `max_length` | אורך מרבי בתווים; חריגה פוסלת את השורה |
| `type` | `text` (ברירת מחדל) / `number` / `date` |
| `format` | בדיקת פורמט: `phone` / `email`. כברירת מחדל מפיקה **אזהרה** (לא פוסלת). `phone` גם מנקה למספרים בלבד |
| `format_severity` | `warning` (ברירת מחדל) או `error` — האם כשל ב-`format` פוסל את השורה |
| `decimals` | (ל-`type: number`) מספר ספרות אחרי הנקודה בפלט |
| `transform` | רשימת טרנספורמציות בשם (ראו למטה) |
| `value_map` | מילון המרה `{ערך במקור: ערך בפריוריטי}` |
| `default` | ערך שנכנס כשהתא ריק (או הערך הקבוע בעמודה ללא `source`) |
| `title` | שם השדה בעברית — מוצג בכותרת הטבלה ובפאנל המיפוי. גובר על התואר שמגיע מ-`specs/` |
| `lookup` | שם טבלת עזר (`currencies` / `paycodes`) — ממיר קוד **או** תיאור בעברית לקוד התקני. ערך שלא זוהה מפיק אזהרה |
| `generate` | `rownum` = מספור שורות רץ אוטומטי (במקום קריאה מהמקור) |
| `manual` | `true` = עמודה שהמיישם ממלא בטבלה; הערך שהוקלד נשמר ולא נדרס ב-`default` |
| `exclude` | `true` = העמודה מוצגת בטבלה אך **אינה נכתבת לקובץ הפלט**. `manual`+`exclude` יחד = עמודת ההערות למיישם |

> **חשוב:** סדר העמודות ב-`columns` הוא **הסדר המדויק** של העמודות בקובץ הפלט —
> הוא חייב להתאים לסדר השדות בהגדרת ה-Interface בפריוריטי (בממשק הוובי אפשר גם
> לסדר עמודות בגרירה).

### מיפוי אחד לכמה פורמטים של קבצים (כינויים)

כשמספר קבצי מקור שונים נטענים לאותו ממשק (למשל יצוא לקוחות רגיל **ו**אינדקס
חשבונות מחשבשבת — שניהם למסך CUSTOMERS), אין צורך בשני מיפויים. מגדירים לכל שדה
רשימת **כינויים** ב-`source`, והכלי מתאים אוטומטית את העמודות שקיימות בקובץ שהועלה:

```yaml
- source: ["מספר לקוח", "מפתח חשבון", "קוד לקוח"]   # כל אחד מהשמות האלה יתאים
  target: CUSTNAME
  required: true
```

שדה חובה שאין לו אף עמודה מתאימה — יפיק שגיאה ברורה. שדה רשות שחסר — יישאר ריק.

### קטלוג שדות רשמי (אכיפה אוטומטית מ-`specs/`)

לכל מסך אפשר להוסיף **מפרט שדות רשמי** ב-`specs/<SCREEN>.yaml` — קטלוג השדות של
המסך בפריוריטי (שם שדה → אורך מרבי, חובה, טיפוס, דיוק עשרוני, בוליאני). כשקיים מפרט,
הכלי **מעשיר ואוכף אוטומטית** את המגבלות על כל עמודה שה-`target` שלה מופיע בקטלוג —
בלי צורך לחזור על `max_length`/`type`/`required` בכל מיפוי. ערך מפורש במיפוי תמיד גובר.

הפרויקט כולל את `specs/CUSTOMERS.yaml` (קטלוג של 226 שדות ממסך הלקוחות), וכן
`specs/JOURNAL.yaml`, `specs/PART.yaml` ו-`specs/SUPPLIERS.yaml` (נוצרו
מייצוא הגדרות המסך). כך, למשל, `CUSTNAME` מוגבל אוטומטית ל-16 תווים, `CUSTDES`
ו-`STATDES` הם חובה, `CREATEDDATE` הוא תאריך, ושדות דגל נבדקים כ-Y/N. אם מיפוי
מפנה לשדה שאינו בקטלוג או לשדה לקריאה-בלבד — מוצגת אזהרת מיפוי.

> **חשוב:** קובצי `specs/` נוצרים מקטלוג השדות של הלקוח ו**אין לערוך אותם ביד** —
> ריענון עתידי של הקטלוג ידרוס את השינוי. כדי לשנות התנהגות של שדה מסוים, יש לציין
> את המפתח (למשל `title` או `max_length`) **בקובץ המיפוי**, שתמיד גובר על הקטלוג.

### מסמכים עם מסכי-משנה (שורות בת)

לטעינת מסמך עם שורות בת (מחירונים לפריט, אנשי קשר ללקוח וכו') — מוסיפים למיפוי
`document: true` וקטע `subforms:`. כל שורה באקסל = שורת בת, והמפתח (למשל מק"ט)
חוזר על פני מספר שורות **בלי** להיחשב כפילות. הכלי מייצר **שני קבצי טעינה**:
קובץ אב (ייחודי לפי המפתח) + קובץ לכל מסך-משנה (מקושר במפתח). ראו דוגמה מלאה
ב-`mappings/PARTPRICE.yaml` וקובץ `examples/pricelist.xlsx`.

```yaml
document: true
key_fields: [PARTNAME]
columns:                 # עמודות האב
  - source: [מקט]
    target: PARTNAME
    required: true
subforms:
  - name: PRICELIST      # קובץ מסך-משנה נפרד, מקושר ב-PARTNAME
    columns:
      - source: [מחירון]
        target: PLNAME
        required: true
      - source: [מחיר]
        target: PRICE
        type: number
```

### ולידציות ישראליות

- `format: idnum` — בדיקת **ספרת ביקורת** למספר ח.פ./עוסק/ת"ז (אזהרה).
- `format: zip` — בדיקת **מיקוד** תקין (5/7 ספרות, אזהרה).

### היסטוריית טעינות

כל טעינה נרשמת ל-`output/history.jsonl`. עמוד **📜 היסטוריה** בממשק מציג את
הריצות האחרונות (זמן, מסך, קובץ, נקראו/תקינות/נפסלו/אזהרות, משתמש) עם קישורי
הורדה חוזרת לקובץ הטעינה, לשורות הפסולות ולדוח.

### שגיאות מול אזהרות

- **שגיאה** (אדום) — פוסלת את השורה: חובה חסר, אורך חורג, מספר/תאריך לא תקין,
  ערך מחוץ ל-`value_map`, כפילות במפתח.
- **אזהרה** (כתום) — **אינה פוסלת**: השורה נכללת בקובץ הטעינה, אך מסומנת לבדיקה.
  ברירת המחדל של בדיקות `format` (טלפון/דוא"ל לא תקין). בממשק הוובי האזהרות מוצגות
  בצהוב עם מונה נפרד; ב-CLI הן מרוכזות בדוח.

## ניקיון נתונים אוטומטי

מופעל על **כל** תא, ללא צורך בהגדרה:

- הסרת רווחים מיותרים מהקצוות וצמצום רצפי רווחים לרווח בודד
- הסרת תווי כיווניות ותווים בלתי-נראים (RTL/LRM, RLM, BOM, ZWSP וכו')
- המרת רווחים מיוחדים (NBSP) לרווח רגיל
- **מספרים שאקסל שמר כטקסט** — הסרת מפרידי אלפים, סימני מטבע ורווחים (`"1,234"` → `1234`)
- **תאריכים שאקסל שמר כמספר סריאלי** — המרה אוטומטית לתאריך (למשל `45000` → תאריך אמיתי)

### טרנספורמציות בשם (בשדה `transform`)

| שם | פעולה |
|---|---|
| `strip` | הסרת רווחים מהקצוות |
| `upper` / `lower` / `title` | שינוי אותיות (לטקסט לועזי) |
| `collapse_spaces` | צמצום רצפי רווחים |
| `remove_spaces` | הסרת כל הרווחים (נוח לטלפונים/מק"טים) |
| `digits_only` | השארת ספרות בלבד |

## ולידציות

שורה שנכשלת **באחת** מהבדיקות נפסלת (עם סיבה מפורטת בעברית):

- **שדה חובה** — `required: true` והתא ריק
- **אורך מרבי** — חריגה מ-`max_length`
- **מספר לא תקין** — `type: number` והערך אינו מספר חוקי
- **תאריך לא תקין** — `type: date` והערך לא ניתן לפירוש כתאריך
- **ערך מחוץ ל-`value_map`** — ערך שאינו קיים ברשימת ההמרה
- **כפילות במפתח** — שילוב ערכים ב-`key_fields` שכבר הופיע (הראשון נשמר, הבאים נפסלים)

### קידוד (windows-1255)
תו שאינו קיים בטבלת `windows-1255` (למשל אמוג'י או אות מיוחדת) **אינו פוסל** את השורה —
מוצגת אזהרה עם מספר השורה והשדה, והתו מוחלף ב-`?` בקובץ הפלט. כדאי לבדוק אזהרות אלו לפני הטעינה.

## איך מוסיפים מסך יעד חדש

1. **צור קובץ מיפוי** חדש: `mappings/<SCREEN>.yaml` (העתק את `CUSTOMERS.yaml` כנקודת פתיחה).
2. **מלא את הגדרות המסך** — `screen`, `delimiter`, `encoding`, `date_format`, `key_fields`.
3. **הגדר את העמודות** לפי הסדר המדויק של השדות בהגדרת ה-Interface בפריוריטי:
   - `source` = כותרת העמודה בקובץ האקסל שלך.
   - `target` = שם השדה (העמודה) בטבלת/מסך היעד בפריוריטי.
4. הרץ עם `--dry-run` כדי לבדוק ולידציות בלי לייצר קובץ, תקן, וחזור.
5. כשהכול תקין — הרץ בלי `--dry-run` וטען את הקובץ בפריוריטי.

## התאמה מול הגדרת ה-Interface בפריוריטי

ההגדרה בפריוריטי נמצאת ב-**System Management → Generators → Interfaces**, בטעינה מסוג
**File Load (מקובץ)**. ודא התאמה מלאה בין קובץ המיפוי לבין הגדרת הממשק:

| בקובץ המיפוי | חייב להתאים ל... בפריוריטי |
|---|---|
| **סדר** ה-`columns` | סדר השדות/העמודות בהגדרת ה-Interface |
| `delimiter` | תו המפריד שהוגדר ב-Interface (Tab / פסיק / Pipe) |
| `encoding` | קידוד הקובץ שה-Interface מצפה לו (בדרך כלל `windows-1255` באון-פרם) |
| `include_header` | האם ה-Interface מוגדר לדלג על שורת כותרת ראשונה |
| `date_format` | פורמט התאריך שהשדות מצפים לו |
| שמות ה-`target` | שמות השדות (עמודות) בטבלת הטעינה |

טיפים:
- שמות שדות ועמודות ניתנים להתאמה אישית לכל אתר — התאם את ה-`target` לשמות שאצל הלקוח.
- שדות מותאמים (Custom) צריכים מספר עמודה גדול מ-500 ולהתחיל בקידומת 4 אותיות של הלקוח
  (למשל `XXXX_OPENDATE`).
- אין להכניס רשומות ישירות לטבלאות — הטעינה חייבת לעבור דרך ה-Interface / Form Load.
